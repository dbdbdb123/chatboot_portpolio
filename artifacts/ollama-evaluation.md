# Docker + 실제 Ollama 평가

측정일: 2026-09-15. 로컬 배포: http://127.0.0.1:8000

## 환경과 방법

- Docker Desktop Linux: 6 CPU, 메모리 약 7.45 GiB. AWS EC2 측정값이 아니다.
- 모델: qwen3.5:2b-q4_K_M, ID 124a03c34777, 약 1.9 GB.
- context=2048, parallel=1, think=false. 모델 기본 샘플링 설정 유지.
- 7개 시나리오를 순차로 각 1회 실행. 최초 요청에는 모델 로딩 시간이 포함될 수 있다.
- 첫 응답은 첫 SSE delta 시간이며, 토큰 단위 TTFT와 다르다. 전체 시간에는 도구 실행과 후속 추론을 포함한다.
- 자동 평가는 도구 이름·키워드 검사이므로 의미 정확도나 지시 준수율이 아니다.
- API 오류 없이 7/7 완료. 자동 조건 통과 5/7. 인사·문서·짧은 답변에는 별도 검토 사항이 있다.

## 관찰 및 개선 우선순위

1. 이전 대화 회상 실패를 먼저 재현하고 모델·프롬프트별 반복 평가가 필요하다. 이번 Ollama 로그에서는 잘림 표시가 0이므로 컨텍스트 초과를 원인으로 단정할 수 없다.
2. 계산기는 단위 테스트와 달리 이 실제 요청에서 호출되지 않았다. 최종 숫자만 맞더라도 도구 선택은 실패로 처리했다.
3. 문서 검색은 실행되지만 모델이 읽는 줄과 인용하는 줄이 달라질 수 있다. 인용 검증과 검색어/구간 선택 개선이 필요하다.
4. 불필요한 설명·언어 혼합·빈 think 태그가 발생했다. 짧은 한국어 답변과 출력 형식 준수 평가를 보강해야 한다.
5. 도구를 요구한 4개 시나리오 중 3개가 필요한 도구를 모두 호출했다. 필수 도구 5종 중 실제로 4종이 실행되었다.

측정 후 스냅샷: 앱 79.23 MiB, Ollama 2.553 GiB. 최대 사용량이나 부하 중 평균이 아니다.
7개 단발 샘플이므로 처리량·p95·일반적인 정확도로 해석하지 않는다. OCR/MCP 외부 연동은 평가하지 않았다.

## 재실행

프로젝트 루트에서 서버 실행 후:

```powershell
.venv\Scripts\python.exe scripts/evaluate_ollama.py --output artifacts/ollama-evaluation-next.json
```

원본 답변, 도구 인자, 호출 시점과 자동 채점 결과는 `ollama-evaluation.json`에 저장되어 있다.
현재 배포는 그대로 실행 중이며 측정을 위해 제품 코드나 모델 설정을 변경하지 않았다.
